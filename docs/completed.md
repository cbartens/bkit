## bkit CI hotfix — drop dual pnpm SoT (KN-3) — BAR-130 (2026-05-05)

- **Category:** infra
- **Artifacts:** `docs/plans/logs/bar-130-ci-lint-scaffolding/debug-summary.md`, `docs/plans/logs/bar-130-ci-lint-scaffolding/debug-failure-diagnose-1.md`, `docs/plans/logs/bar-130-ci-lint-scaffolding/debug-failure-remediate-1.md`. Hotfix branch `fix/bar-130-ci-pnpm` (cut from `origin/dev` after squash-merge made original feat branch unrebaseable).
- **Summary:** Second ship cycle for BAR-130. Post-merge dev CI run [25354307730](https://github.com/cbartens/bkit/actions/runs/25354307730) on commit `8646711` failed at `Setup pnpm` with `Error: Multiple versions of pnpm specified` — pnpm/action-setup@v4 enforces single-SoT and aborted because both `with: version: 10` (workflow YAML) and `pnpm@10.33.0` (`package.json#packageManager`) were declared. Same defect existed in `.agents/templates/.github/workflows/ci.yml` with `version: {{PNPM_VERSION}}` — would have shipped to every consumer running `bkit install --ci`. **Fix:** dropped `with: version:` block from both ci.yml files (bkit-self + consumer template); `package.json#packageManager` becomes the single SoT (Corepack-aware). Added KN-3 warning comments inline in both files. Annotated `bkit-tokens.ts` `resolvePnpmVersion` (kept for interface stability; retired in v0.2 per pending entry — `{{PNPM_VERSION}}` token is now dead code). Two regex-based regression guards added to `bkit-modules.integration.test.ts` (lines 534–557) asserting neither ci.yml sets `with.version:` for `pnpm/action-setup@v4`. Pre-existing `toContain("10")` assertion updated (broken by template token removal). 175 tests pass; typecheck + format:check + slop-scan + lint:prose green. No version bump (still v0.1.2).
- **Related:** BAR-130, KN-3 (single-SoT rule), run 25354307730, `docs/pending.md` v0.2 `{{PNPM_VERSION}}` retire entry, `.github/workflows/ci.yml`, `.agents/templates/.github/workflows/ci.yml`, `.agents/scripts/bkit-tokens.ts`, `.agents/scripts/bkit-modules.integration.test.ts`.
