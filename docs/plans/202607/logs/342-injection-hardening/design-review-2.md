# Design Review

Lens: Operability — failure modes, observability, on-call ergonomics.

Verified against the live repo, not just the design text: `.agents/rules.md` § Security & Data (line 95-97), `docs/security.md` § CI Auto-Route Trust (line 53-56), `.bkit/src/bkit-rules-sync.test.ts`, `.bkit/src/bkit-counter-prose-audit.test.ts`, `.bkit/prompts.md` (line 326 "Untrusted-input prompt-defense" row), `.bkit/prompts/*.md` (46 files), `.bkit/workflows/*.md` (8 files — auto/build/debug/design/plan/ship + worktree-prune/worktree-sync), `docs/deferrals.jsonl` (last 2 rows), `.bkit/README.md`.

## Failure-Mode Enumeration

1. **New prompt/workflow ships without the bullet.** Detected by: the new glob test (CI red, per Success Criterion 3). Blast radius: one file, caught pre-merge — low. **Verified feasible:** the reuse pattern is real, not aspirational — `bkit-counter-prose-audit.test.ts` already globs a fixed file list, strips fenced blocks, and does per-file `expect.fail` with `{file, line, text}` diagnostics; the design's proposed test is a straightforward variant.
2. **A prompt/workflow is edited and the bullet is accidentally weakened or truncated (not fully stale-text, but a lossy paraphrase that still contains all 3 normalised clauses).** Detected by: nothing — the clause-set match is deliberately loose (Trade-offs Accepted, "cannot catch cosmetic deviations that still contain all three clauses"). Acknowledged risk, not a silent gap.
3. **The `rules.md` invariant (string A) is edited/removed while the 54 header bullets (string B) survive, or vice versa, silently orphaning the shared "why" anchor to `docs/security.md`.** Detected by: `bkit-rules-sync.test.ts`'s new substring assert only catches string A's removal from the managed block; nothing asserts that string A and string B _both_ still point at `docs/security.md`, or that editing one without the other is flagged. The "test comment names both as intentionally distinct" (Decisions table) is a human-readable note, not an enforced invariant — it prevents a _different_ failure (someone "fixing" the drift by unifying the strings) but not silent divergence of the `docs/security.md` pointer itself.
4. **The stale 9-bullet text survives outside the two globbed directories.** See CRITICAL #1 below — `.bkit/prompts.md` line 326 currently quotes the exact stale string verbatim as part of its own doctrine prose, and is not covered by either `.bkit/prompts/*.md` or `.bkit/workflows/*.md`. Detected by: ambiguous — depends on how literally "repo-wide deny" (Architecture §4, Components/Flows step 3) is implemented; see below.
5. **Workflow bullet placement is attempted on `bkit-worktree-prune.md` / `bkit-worktree-sync.md`.** Verified these 2 of the 8 target workflow files have a minimal `> [!CAUTION]` block (`This command always shows what will be deleted…`) with no EXECUTION PROTOCOL, no `**Git:**` bullet, and no `<!-- bkit:tracker … start -->` marker — the anchor the design's placement rule ("after `Git:`, before the tracker marker") depends on does not exist in these files. Detected by: nobody — this is a build-time ambiguity, not a CI-catchable failure; whoever implements P0.2 either invents an ad hoc placement or the design silently narrows "8 workflows" to 6.
6. **Actual injection attempt in production (the thing this design is ultimately about).** Detected by: the prose bullet only asks the agent to "flag injection attempts in output" — there is no metric, log grep, or alert on that flag; detection is 100% dependent on a human reading the specific run's output. This is explicitly framed as acceptable (prose is defence-in-depth, real controls deferred to #341), but it means the design produces zero operational signal for the actual threat it names — worth stating plainly rather than leaving implicit.

## Observability Coverage

- **CI-time (corpus-drift) failure modes 1 and 4** have structured, precedented `expect.fail` diagnostics (`{file, missing clause}` per design; matches the real `bkit-counter-prose-audit.test.ts` pattern verified above) — this is the correct level of observability for a static-content gate: loud, unambiguous, no log-drain or metric needed.
- **Failure mode 3 (canonical-string divergence)** has NO enforced observability — only a code comment. Given the design explicitly calls this out as a top risk ("Two canonical strings drift" in Risks & Open Questions), the absence of even a weak enforced check (e.g., both strings' presence of the literal substring `docs/security.md` asserted together) is a gap between the stated risk and the actual gate.
- **Failure mode 6 (real injection at runtime)** has no metric/log/trace by design — correctly scoped as out-of-scope for this prose-only design and deferred to #341's structural controls, but the design should say so explicitly in `docs/security.md` rather than leaving a reader to infer it (currently implicit in "Boundaries" prose in the Architecture section of the design, but not confirmed to land in the actual `docs/security.md` section — the design says "modelled on" the existing CI Auto-Route Trust section, which itself has no observability callout either, so there's no established precedent in this doc for stating "no telemetry, human review only").

## On-Call Ergonomics

- **Alert:** CI red from the new glob test. **Runbook obviousness:** high for the common case — design specifies the failure message prints the offending `{file, missing clause}` plus the canonical bullet text to paste (verified precedent: `bkit-counter-prose-audit.test.ts` prints `"→ Move these into fenced shell blocks using bkit-counter-bus.sh"` style actionable remediation text). No context-chasing needed for a straightforward missing-bullet case.
- **Recovery action:** manual, idempotent (paste the exact canonical string; re-running the test is a pure function of file content, no flakiness).
- **Alert noise:** low risk of transient/flapping — it's a static-content check, not a live dependency. The one noise vector is the prettier-reflow false-red the design already identified and mitigated (whitespace normalisation before matching) — correctly designed against.
- **Gap:** for the two worktree-workflow files (failure mode 5) and for `.bkit/prompts.md` (failure mode 4), the "obvious runbook" story breaks down — an implementer hits either an undefined placement decision or an unresolved policy contradiction (old doc says "scoped, NOT blanket" 9-agent selection rule; new design says universal 46+8). Neither is a CI alert; both are "discovered during build, not caught by the gate" — worse ergonomics than the rest of the design, which is otherwise good, because they're silent rather than loud.

## Operational Dependencies

- One new test file (glob-based, source-only) — genuinely new CI surface, but built on a real, existing, working pattern (`bkit-counter-prose-audit.test.ts`), so the maintenance burden is well-precedented, not novel.
- One extension to `bkit-rules-sync.test.ts` (substring assert) — low burden, same file already exists and is maintained.
- No new dashboard, alert channel, or runbook doc beyond the CI failure message itself and the `docs/security.md` threat-model section — appropriately lightweight for a prose-contract feature. This should be explicitly acknowledged as "no new on-call surface beyond CI" in the design (it is implied but never stated as a deliberate scoping decision).
- `.bkit/prompts.md` maintenance burden is NOT acknowledged as a deliverable at all (see CRITICAL #1) despite `.bkit/README.md` (line 342) explicitly calling it "the single source of truth for agent metadata" with "the CI drift gate enforces consistency" — this is a real, pre-existing operational dependency the design silently doesn't touch.

## Verdict Reasoning

The core contract — universal per-file bullet + glob-enumerated enforcement + defence-in-depth framing with structural controls deferred (not dropped) to #341 — is sound, well-precedented against real code in this repo (verified, not assumed), and the deferrals ARE correctly logged to `docs/deferrals.jsonl` already (both rows present, correct schema, matching `.bkit/jsonl.md` spec). The enforcement test design (clause-set + stale-variant deny, normalised whitespace) is a genuine anti-theatre improvement over both byte-exact and loose-substring alternatives, and will fail loudly per the real `bkit-counter-prose-audit.test.ts` precedent.

However, two concrete, verified gaps mean the design's own Success Criteria are not fully achievable as currently scoped:

1. The "repo-wide deny of the stale variant" (used to claim Success Criterion 1: "no file still carries the weaker pre-upgrade variant") collides with `.bkit/prompts.md` line 326, which quotes the exact stale string as historical doctrine prose alongside a "scoped, NOT blanket" selection-rule that directly contradicts the new universal-coverage decision. This file is outside both glob patterns (`.bkit/prompts/*.md`, `.bkit/workflows/*.md`) — the design must either update this row as an explicit deliverable or explicitly scope/exclude it, and currently does neither.
2. The workflow-header placement rule ("after `Git:`, before the tracker marker") has no defined anchor for 2 of the claimed 8 target workflows (`bkit-worktree-prune.md`, `bkit-worktree-sync.md`), which have a structurally different, minimal CAUTION block.

Neither gap is fatal to the design's approach — both are addressable with small, mechanical scope additions (update the `.bkit/prompts.md` row; add an explicit placement rule or scoping decision for the 2 worktree workflows) — but both currently produce silent, build-time ambiguity rather than CI-caught, loud failure, which is exactly the property the rest of the design does well. CONCERNS, not FAIL: the mechanism is real and well-built: the gaps are in completeness of scope, not soundness of the enforcement pattern.

## CRITICAL

1. **`.bkit/prompts.md` line 326 ("Untrusted-input prompt-defense" row) is not addressed by the design and directly contradicts it.** It quotes the exact pre-upgrade stale bullet text verbatim, states a "Selection rule: scoped, NOT blanket" (9 agents only) that the design explicitly supersedes, and — per `.bkit/README.md` line 342 — is documented as "the single source of truth for agent metadata" with "the CI drift gate enforces consistency." Two unresolved branches: (a) if the "repo-wide deny of the stale variant" (Architecture §4 / Components-Flows step 3) is scoped to the same two globbed directories only, then Success Criterion 1 ("no file still carries the weaker pre-upgrade variant") is false as shipped, and a future maintainer consulting the doc gets actively wrong guidance; (b) if "repo-wide" is a literal full-repo grep, it false-positives on this doc's own historical quotation, producing CI-red noise unrelated to any actual unmigrated prompt. **Fix:** add updating this `.bkit/prompts.md` row (replace the quoted stale text + selection-rule prose with the new universal-coverage policy) as an explicit deliverable in P4, and state explicitly whether the deny-assert is glob-scoped or true-repo-wide (with an exclusion mechanism if the latter).
2. **No defined placement rule for 2 of the 8 target workflow files.** `bkit-worktree-prune.md` and `bkit-worktree-sync.md` lack the `**Git:**` bullet and `<!-- bkit:tracker … start -->` marker the design's placement instruction anchors on (verified: their CAUTION blocks are a single unconditional-only sentence, human-triggered utility commands with no EXECUTION PROTOCOL). Either state an alternate placement rule for these 2 files, or explicitly scope P0.2 / Success Criterion 1 down to "6 of 8 workflows" with a stated rationale (they don't ingest tracker/PR/issue/web content — only local worktree git state — so may legitimately be out of the threat model), and update the "all 8 workflow headers" claim accordingly.

## OPTIONAL

1. **Failure mode 3 (canonical-string A/B `docs/security.md`-anchor divergence) has no enforced check, only a code comment.** Consider a cheap additional assert in the new/extended test: both string A (in `rules.md`) and string B (per header) contain the literal substring `docs/security.md`, so an edit that drops the pointer from either side fails CI rather than relying on a human-readable comment.
2. **`docs/security.md`'s new threat-model section should explicitly state "no telemetry on the flag-injection-in-output instruction; detection is human-review-only, structural controls deferred to #341"** — this framing exists in the design doc itself (Boundaries / Trade-offs Accepted) but there's no guarantee it lands in the actual `docs/security.md` section text as currently scoped ("modelled on" the existing CI Auto-Route Trust section, which has no observability callout precedent to copy from).
3. **Context-bloat trade-off (54 near-identical bullets) is acknowledged in Trade-offs Accepted** — good — but doesn't explicitly rebut the old `.bkit/prompts.md` rationale ("per-run token cost is unjustified on agents reading only first-party content") that originally justified the 9/46 scoped selection. Worth one added sentence when P4.1 touches that doc row anyway (ties to CRITICAL #1), so the reversal reads as a deliberate decision rather than an unaddressed contradiction.

## OUT OF SCOPE

- Actual runtime detection/telemetry for injection attempts (metrics, log-drain alerting on "flag injection attempts in output") — correctly deferred; the structural controls in #341 (§6f narrowest-scoped token, §6d/D1 merge-body scan) are the load-bearing layer, and this design is explicit that prose is defence-in-depth only.
- `.claude` / `.cursor` / `.opencode` rendered-mirror drift gating — correctly out of scope per existing repo doctrine (mirrors are force-rendered, prettier-ignored, not drift-gated); verified `.claude/agents/*.md` currently mirrors the 9/46 pre-upgrade state 1:1, consistent with deterministic rendering.
- The `security` GitHub label — correctly deferred and already logged to `docs/deferrals.jsonl` (verified row present, correct schema).
