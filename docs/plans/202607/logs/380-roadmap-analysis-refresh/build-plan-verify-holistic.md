## Integration Gaps

5 gaps. Three are cross-sub-plan handoff drops (a commitment made by one sub-plan that no later sub-plan picked up); two are consistency/hygiene defects on the same seam.

1. **Ship close never regenerates the status board.** `bkit-ship.md` contains zero `bkit_roadmap_fold` call sites (grep-verified: design/plan/build/debug and `bkit-roadmap.md` all call it, ship does not). Sub-plan 1 explicitly deferred this — "The `roadmap-status` regenerate at ship, the analysis Step 10 wiring, and the cadence step land in sub-plans 2/3" (`-plan-1.md`, § `[MODIFY] .bkit/workflows/bkit-ship.md`) — and neither sub-plan 2 (Tasks 8–12) nor sub-plan 3 (Tasks 13–15) has a task for it. Net effect: at ship, `@bkit-ship-update-docs` appends the `SHIPPED` row and the verdict greens off it, but the board still shows the FID under Build/Debug until some other FID's design/plan/build/debug close happens to run a full regenerate.
2. **The `### Ship` (in flight) section is permanently empty and ships plan-internal text to consumers.** `bkit-roadmap-fold.sh:180-181` emits the literal `### Ship _(in flight — populated by ship-close wiring, sub-plans 2/3)_` followed by a hardcoded `_(none)_`. Two problems: the promised wiring never arrived (gap 1), and the six-state ladder (`DESIGNED|PLANNED|BUILT|DEBUGGED|SHIPPED|ABANDONED`, Addendum 3 § N) has no in-flight-ship state, so no ledger row can ever populate that section — design § K's "`## Ship` (in flight) and `## Shipped` (last 10) are separate sections" is unsatisfiable as built. The string renders into the consumer's `docs/roadmap.md`, so bkit's internal sub-plan numbering becomes shipped surface.
3. **`/bkit-roadmap` drops the `ROADMAP_SCAN_COVERAGE` counter row.** Sub-plan 3's Acceptance Scenario step 3 (and sub-plan 1's Concrete Example step 3) state the utility "stamps 'scanned N of M', and appends a `ROADMAP_SCAN_COVERAGE` counter row". Sub-plan 2 then fixed `counterSource: "shell-bus"` — the value is derived by the caller's shell from the leaf's report text, not self-reported by the leaf (`bkit-ship.md:1112-1118`, `:1134-1136`). `bkit-roadmap.md` reuses the leaf but implements no shell-side derivation and no `stats.jsonl` append, so the on-demand path records no coverage at all. The `shell-bus` decision was applied in the ship path only.
4. **Third scratch-file path is undeclared.** `bkit-roadmap.md:39` tells the leaf to write `.bkit/.roadmap-refresh-on-demand.md` and calls it "(gitignored, not committed)". It is not: `git check-ignore -v .bkit/.roadmap-refresh-on-demand.md` exits 1. The two sibling `#380` scratch paths (`.bkit/.roadmap-tracker-rows-*.json`, `.bkit/.roadmap-reverse-sync-*.json`) were added to `.gitignore` and `.bkit/templates/gitignore`. Consequence: build/debug closes stage with `git add -A`, so a stray on-demand report gets committed, and the shipped claim is false.
