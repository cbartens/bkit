# Design Review

Lens: Operability — failure modes, observability, the honesty of the output under degradation.

Reviewed: `docs/plans/202607/logs/402-audit-engine-orchestrator/design-v1-draft.md` (Pass 4) against `docs/plans/202607/logs/402-audit-engine-orchestrator/design-input.md`. Pass-3 architecture (10-step shape, keystone, finding schema, down-rank contract, operator escapes) is treated as approved and out of bounds; no finding below proposes an alternative to it. All findings are either (a) an unaddressed path to a false-all-clear, (b) a check the design believes exists but does not actually reach the artifact it claims to protect, or (c) a cross-workstream contract with no enforcement leg.

## Observability Coverage

- **F1** — no logs/metric/manifest-echo specified. This is the single most load-bearing gap: Step 6's output row (design-v1-draft.md:353) explicitly lists all four manifest sections and states "gate greps all four manifest sections," but Step 7's output row (design-v1-draft.md:110, 354) lists only "Severity×class matrix + ranked list + per-class appendix + workstream DAG + `## Suggested Guards` appendix" — no mention of `## Missing Lenses` or `## Correlation Coverage`. Step 10 copies `audit-v2-ranked.md` verbatim to `docs/audits/{FID}-audit.md` (design-v1-draft.md:98, 357). If organise does not echo the two coverage manifests forward, the entire false-all-clear invariant this design exists to protect is enforced only inside an intermediate, worktree-local, pre-squash-merge artifact (`audit-v1-synthesis.md`) that no human or downstream consumer (including WS-G, #324, which the design itself says "will eventually gate on these reports," design-input.md §5/§6 couplings) ever reads. **This must be a CRITICAL finding** — missing observability for the design's own headline invariant, in the one place a human reads.
- **F2 / F3** — no test, grep-assert, or manifest state exists for either. The A7 parity test (design-v1-draft.md:601–608) item 1 (four-way slug parity) explicitly includes "the on-disk `bkit-audit-lens-*.md` file set" as a leg — i.e. it checks the _shipped lens files_, not just the two design-owned copies. Item 3 (signal-enum and rule-id parity) checks only "workflow Step-6 copy ↔ synthesiser derived copy" — both authored inside WS-A itself. No leg checks the signal tokens actually emitted by the WS-B/WS-C lens files that are supposed to be the source of the "union" (design-v1-draft.md:256, "Each lens declares its own signal tokens; the union is the canonical signal enum"). This asymmetry means the slug contract is machine-enforced end-to-end and the signal contract is not — exactly the failure the parity-test mechanism was built to close everywhere else.
- **F4** — `## Applicability Overrides` records an audit-trail line (design-v1-draft.md:106, 225), but that section lives in `audit-stack.md` (Step 3), and the per-lens/per-manifest reason-string vocabulary (design-v1-draft.md:276, 318) has exactly four tokens, none of which distinguishes "auto-detected false" from "override-forced false." A lens self-no-ops by reading the post-override merged flag value; it has no way to know (and the design gives it no instruction to check) whether the value it saw came from detection or an override.
- **F5** — same root cause as F1/F4: the distinguishing text ("excluded by `[lenses=...]` operator," design-v1-draft.md:318, 362) exists only in `## Missing Lenses`, which is not proven to reach the final report.
- **F6** — no coverage-evidence field is specified for any of the 18 lens artifacts. `audit-stack.md`'s `## Detection Coverage` (filesScanned, packagesFound, confidence) exists only for the stack-detect step; nothing analogous exists per-lens. The "sanity-probe-before-emit" mechanism (design-v1-draft.md:65, 570) is specified only for _conditional_ lenses reacting to a true flag with no surface evidence — there is no equivalent mechanism for a _universal_ lens whose scope silently comes up empty.
- **F7** — Failure Path (design-v1-draft.md:148) is fully enumerated and this pass is explicitly rewriting it (Task 1); it has no skill-cleanup line. A3 (design-v1-draft.md:595) says the skill-install agent reuses "build/ship skill machinery verbatim incl. uninstall/prune," implying uninstall is a normal-path behavior of that one step, not a workflow-level guarantee independent of where the pipeline later dies.
- **F8** — no fixture/consumer-repo validation requirement is listed for `ai-llm` in WS-C's acceptance (design-v1-draft.md:639–646). The equivalent gap for `ui-ux` is explicitly named and solved ("Validate `ui-ux` against a consumer/sample UI repo — bkit cannot dogfood it," line 644); the same reasoning applies to `ai-llm`'s finding-emission path but is not extended to it.
- **F9** — `## Truncated` (design-v1-draft.md:279) is a single count + floor per lens artifact; `debt`'s three-way internal cap split (line 281, 389) has no corresponding three-way truncation report.

## On-Call Ergonomics

This workflow has no recurring/scheduled on-call in scope (WS-G, #324, out of bounds) — the "on-call" reader here is the developer who invoked `/bkit-audit` ad-hoc and reads `docs/audits/{FID}-audit.md`, and (per design-input.md's cross-workstream note) a future automated WS-G gate consumer.

- **Runbook obviousness from the report alone:** poor for F1/F4/F5. A developer reading only `docs/audits/{FID}-audit.md` currently has no basis to distinguish "this repo has no DB" from "an operator excluded/overrode this," or "this run covered all 18 lenses" from "this run covered 6." The recovery hint pattern the design uses elsewhere (Failure-Path recovery hint, design-v1-draft.md:364) is a good model — none of F1/F4/F5 gets one.
- **Recovery action:** for F3 (cap-evicted leg), the design already names the recovery ("`[lenses=slug]` single-lens re-run," line 780) but nothing in the report prompts the reader to take it, because the eviction is invisible at the correlator's leg-state layer.
- **Alert/verdict noise vs. under-alerting:** the verdict-mapping table (design-v1-draft.md:543–549) is well-tuned for the cases it enumerates (N/A-caused unevaluable → PASS so bkit's own dogfood stays green; crashed/excluded → CONCERNS). But because F1–F3 can each degrade a rule to "no match"/PASS without ever reaching the `unevaluable` branch, the verdict-mapping table's careful tuning is undermined by paths that never enter it at all.

## Operational Dependencies

- A7's parity test (design-v1-draft.md:601) is a new shipped `.bkit/src/` test file — acknowledged in the doc's own Trade-offs ("A wider gate surface," line 766) but its coverage should be widened per F2/F3 rather than accepted as-is.
- Step-6/Step-7 boundary needs an explicit propagation contract (which sections of `audit-v1-synthesis.md` survive verbatim into `audit-v2-ranked.md`) — this is new required documentation, not new machinery; it should be a one-paragraph addition to A5's scope, not a new agent or step.
- No new dashboard/alert surface — audit is ad-hoc, terminal, no scheduling (correctly out of bounds here).

## Verdict Reasoning

CONCERNS, not FAIL: none of the gaps found require re-litigating the approved architecture. Each is closeable by an additive clause inside the sub-plans already chartered (A5/A6 for F1, F4, F5, F9; A7 for F2; A1/A4 for F3, F6; A3/A6 Failure Path for F7; WS-C acceptance for F8) — no new agent, step, artifact file, or contract shape is implied. But F1 in particular is severe enough that shipping the design as currently worded risks landing the exact class of defect the whole reconciliation pass exists to prevent (a report that reads clean because a safety mechanism silently never reached the reader), so this cannot pass as-is without at least F1 and F2 being pinned down before `/bkit-plan` consumes the doc.

## CRITICAL

1. **(F1) No stated propagation of `## Missing Lenses` / `## Correlation Coverage` from Step 6's `audit-v1-synthesis.md` into Step 7's `audit-v2-ranked.md` or the Step-10 `docs/audits/{FID}-audit.md`.** Organise's owned-sections list (design-v1-draft.md:110, 354) does not include either manifest. Fix: add an explicit line to A5's scope (and the Components & boundaries bullet at line 110) stating organise carries both manifests through verbatim (in addition to, not instead of, its own matrix/ranked-list/appendix/DAG sections), and extend organise's in-agent self-verify (already checking "coverage orphan, DAG cycle, down-rank violation," line 354) to assert both manifests are present in its own output before it can emit PASS/CONCERNS.
2. **(F2) The signal-token contract has no on-disk enforcement leg.** A7 parity-test item 3 (design-v1-draft.md:605) checks only the workflow-vs-synthesiser copies, unlike item 1's four-way check which includes the shipped lens files. Fix: widen item 3 to a three-way (or four-way, mirroring item 1) check against the actual `signal:` values used in `.bkit/prompts/bkit-audit-lens-*.md` frontmatter/body, or against a fixture corpus of expected findings per lens.
3. **(F3) The correlator's leg-state resolution (present/absent/unobserved) cannot distinguish "genuinely absent" from "present but evicted by the 25-cap/5-reserve."** A lens that is `ran (truncated: N)` overall still reports per-subject `absent` for any evicted correlation-eligible finding, and the Correlation Coverage manifest has no state for this — it degrades straight to `no match` → PASS. Fix: either (a) have organise's/synthesiser's leg resolver treat a truncated lens as contributing `unobserved` (not `absent`) for the whole rule, degrading to `unevaluable` rather than `no match`, or (b) require the lens to record evicted correlation-eligible findings' subjects (not full findings) in `## Truncated` so the synthesiser can render a distinct `at-risk (evicted leg)` state.
4. **(F4) The applicability-override escape hatch and genuine flag-false detection are textually indistinguishable in every reason string a reader sees.** Fix: add a fifth reason-string variant (e.g. `{flag}=false (operator override)`) sourced from the same `## Applicability Overrides` audit trail the lens already ignores, and require lenses/synthesiser to consult it when rendering the N/A reason.

## OPTIONAL

- **(F5)** Surface a one-line "partial run: lenses=X,Y excluded" banner at the top of `docs/audits/{FID}-audit.md` (contingent on fixing F1 first, since the manifest row alone is not enough for a skim-reader).
- **(F6)** Add a lightweight per-lens coverage-evidence line (e.g. a `Reviewed: N files` count emitted alongside `## Findings`, even for universal lenses) so a genuinely-empty scan is distinguishable from a genuinely-clean one. Lower priority than F1–F4 since universal-lens scope breakage is a narrower failure surface than the keystone/correlation mechanisms.
- **(F7)** Add an explicit skill-uninstall/prune step to the Failure Path (design-v1-draft.md:148), or state explicitly that Step 4's install+uninstall is atomic within one step and therefore no environment mutation survives past Step 4 regardless of where a later step crashes — whichever is true should be said, since it currently isn't said either way.
- **(F8)** Add an `ai-llm` fixture/consumer-repo validation requirement to WS-C's acceptance criteria (design-v1-draft.md:639–646), mirroring the `ui-ux` line already there.
- **(F9)** Extend `## Truncated` to report per-probe-group counts for `debt` (ledger / suppression / cruft), matching the granularity of its own three-way cap split.
