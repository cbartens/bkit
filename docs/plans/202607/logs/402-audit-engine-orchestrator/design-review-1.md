## PoC Approach

Do not build. The minimal proof that de-risks everything the draft leaves open is a **one-lens vertical slice**, not a horizontal layer:

Author exactly two prompt files — `bkit-audit-lens-reliability.md` (`requires: always`) and `bkit-audit-lens-contract-conformance.md` (`requires: hasDb`) — plus a hand-written `audit-stack.md` fixture and a hand-written three-artifact lens-output set. Then run `bkit-audit-synthesise` standalone against that set, from a prompt file whose tool set is the one A4 will actually ship.

That single run answers the four open buildability questions at once: (1) can the agent execute subject normalisation + alias resolution + the rule table + leg-state assignment from prose alone, and does it produce the same output twice; (2) does it need `Bash`/`awk` to parse the `finding` fences, or is `Read` + `Grep` enough; (3) does `## Correlation Coverage` render `unevaluable (contract-conformance: N/A — not applicable (hasDb=false))` verbatim enough for a grep-assert to be literal; (4) does the `N/A` reason string come out `{flag}=…` or literal `flag=…` (CRITICAL 6).

Cost: two prompts and one agent invocation. No workflow file, no orchestrator, no fan-out.

## Unknowns & Blockers

- **Determinism of the correlation pass is unproven.** The synthesiser is a prompt, not code. § Task 4 rejects the prose-reasoning agent as "non-deterministic: two runs on one repo produce different compositions, nothing can be grep-asserted" (line 746) — but the chosen shape is _also_ executed by an LLM reading a rule table out of prompt text. The rule table, required/amplifier split and leg-state vocabulary genuinely make the _specification_ diffable and reviewable, and the `## Correlation Coverage` grep-assert genuinely makes _silence_ visible. What neither buys is deterministic _execution_: subject normalisation (casefold → non-alphanumerics to `_` → collapse repeats → strip edges), alias table lookup and leg matching are string algorithms an agent will approximate. The honest framing is "declarative and auditable at the spec layer, best-effort at the execution layer, with output-shape asserts as the backstop" — the draft should say so rather than claim the rejected alternative's weakness does not apply. This is not a design change; it is a claim correction plus the PoC above.
- **`subject:` / `signal:` are genuinely additive-optional** (confirmed: lines 233, 244-248, 254 "Absent ⇒ the finding is simply un-correlatable; that is never an error"). WS-B and WS-C prompts remain independently authorable. No finding.
- **`hasDerivedStore` heuristics are unvalidated** — the draft says so itself (line 792) and asks the plan to seed both fixtures. Agreed; leave open.

## Verdict Reasoning

**CONCERNS.** The reconciliation is substantially correct and unusually well grounded: the selective-relocation call is right and was verified path-by-path, the `status.jsonl` pattern-match is faithful (`workflow-meta` genuinely is design-absent — only `bkit-debug.md:224,374,511,800` emits it), the lens arithmetic reconciles (Pass-3's 11 universal + 5 conditional at `80-audit-workflow-design.md:84` + `logic-dupe` + `derived-data` with `supply-chain` moving one seat = 13 + 5 = 18), the `hasCi` deletion leaves no dangling consumer, the `evidence:` field genuinely clears the down-rank fence, `## Suggested Guards` + `guard-ref:` respects every finding-field constraint, and the version decision is closed with reasoning rather than hedged.

It is CONCERNS and not PASS because six specific things would break at build time: two prompt tool-sets are specified such that the agent cannot do its job, the build order makes a shipped test red for three plan runs, one A7 work item points at a row that does not exist in the shipped tree, the lens tally is miscounted in a way that drops an amendment's acceptance criterion entirely, and a dogfood acceptance assert requires a reason-string format the contract that produces it does not specify.

It is not FAIL because none of these touch the approved architecture. Every one is a local correction inside the sections the pass already owns.

## CRITICAL

**C1 — `supply-chain`'s tool set as specified cannot write its own artifact. Every run, including the dogfood.**
Line 616: "forked from the read-only-reviewer skeleton (`Read, Grep, Glob, Write`; `supply-chain` **swaps** `Write` for allowlisted `Bash`)". A lens with no `Write` cannot emit `docs/plans/{YYYYMM}/logs/{FID}/audit-lens-supply-chain.md`, so its slot renders `crashed (` unconditionally — and because this pass reclassifies `supply-chain` to `requires: always`, that is now _every_ audit rather than only CI-bearing repos. The documented Bash allowlist (`git log`, `git rev-parse`, `git cat-file`, `cat`, `jq`, `grep`) contains no write primitive, so there is no workaround inside the allowlist, and using one would violate the read-only posture. The defect is inherited, not invented — `docs/plans/202605/80-audit-workflow-design.md:90` and `:520` both specify `Read, Grep, Glob, Bash` — but this pass restates it, so it propagates rather than closing. It also contradicts the draft's own inventory row 10 (line 393, "Carries allowlisted read-only `Bash`" — additive) and #403's B10. **Fix:** `Read, Grep, Glob, Write, Bash`, stated as additive at line 616, line 393 and in A7's § Tool set patterns sub-row.

**C2 — The synthesiser's tool set is never stated, and the parse mechanism it is handed needs a tool its stated skeleton does not have.**
Line 109 pins the parse to "an awk state machine on `/^```finding$/,/^```$/`". `awk` is a shell invocation and requires `Bash`. The skeleton the synthesiser is forked from is `bkit-design-generate` (`80-audit-workflow-design.md:540`, `bar-199-audit-workflow-design.md:91`), whose shipped frontmatter is `Read, Grep, Glob, Write, Edit` — **verified, no `Bash`**, in `.bkit/prompts/bkit-design-generate.md`. A4's deliverable (line 596) enumerates ten correlation obligations and names no tool set at all. This matters more in Pass 4 than it did in Pass 3, because A4 now also owns subject normalisation, alias resolution and leg-state assignment. Compounding: Pass-3 deliberately _dropped_ `awk` from `supply-chain`'s allowlist as "full-Turing" (`80-audit-workflow-design.md:24`, `:45`), so granting the synthesiser `Bash` + `awk` is a decision that needs recording, and A7's § Tool set patterns list (line 599) has no fourth sub-row for it. **Fix:** decide explicitly — either (a) A4 carries `Read, Grep, Glob, Write, Edit, Bash`, recorded as a decision with an A7 § Tool set patterns sub-row, or (b) drop the awk framing and specify the parse as agent-executed, in which case the determinism claims in § Task 4 and § Approaches Considered need the correction described under Unknowns.

The draft's own § Trade-offs concedes "a wider gate surface … more to keep green" (line 766) but does not notice that the gate is already shipped and already broken by the ordering. **Fix:** make the § Models row a per-sub-plan deliverable (each sub-plan lands its own prompt _and_ its row), and reduce A7 to the wholesale registry-block replacement, § Audit Phase, § Tool set patterns, the Workflow Matrix column, the parity test and the deprecation headers. This does not change A7's `Requires:` for the remaining items.
