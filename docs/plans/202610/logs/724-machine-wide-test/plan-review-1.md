4. **Provider parity is not checked for the lock dir write.** Under this plan, every local `bkit tests run` writes `~/.cache/bkit/machine-lock/` and exits 4 when it cannot. Codex's `workspace-write` sandbox, and any host sandbox that limits writes to the workspace, would deny that path. The result: every `/bkit-build` / `/bkit-debug` gate on that host goes to the Failure Path. `.agents/rules.md` § Provider parity ("MUST work across all providers; verify each") requires this to be covered. The plan has no assumption or open question on host sandboxes, and its Pre-Flight checks only bash / perl / getconf. Fix: add an Open Question (e.g. A) refuse with exit 4 and document each host's writable-path setting; B) fall back to an unlocked run with one stderr line when the cache dir is unwritable inside a known sandbox; C) put the lock under a path every host can write). Name the hosts checked (Claude Code, OpenCode, Codex, Cursor, Antigravity, cloud agents).
