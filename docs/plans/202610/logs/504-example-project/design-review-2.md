# Design Review

Lens: Operability — failure modes, observability, on-call ergonomics.

## Failure-Mode Enumeration

Subject is maintainer-run tooling plus one persistent **public** repo plus bkit-in-a-consumer-repo. "On-call" = the maintainer running the demo/benchmark; detection surface is CLI stderr (`[bkit-example]` for the runner per draft § Flow — bootstrap:1, `[bkit-*]` for bkit), GitHub Checks, and `[bkit-runs]` gate exit codes — no paging stack (`docs/observability.md` § Scope: no telemetry pipeline).

## Verdict Reasoning

`FAIL` — the design is not operable as written because its **pass/fail signal is unsound** and one **irreversible path is guarded only by prose**, on a **public** repo.

The design is otherwise strong and built for this stack: it introduces no server-side dependency, no paging, no metrics; it has a correctly-shaped `[bkit-example]` prefix; and it **closes two gaps the previous review raised** — the gate-chain growth is now asserted at runner setup (§ Flow — run start:3) and the tracker-`none` failure is read back and stopped (§ Flow — run start:3). The destructive reset has a named pre-mutation preflight and an idempotent re-run. Ship-gate refusals (codes 10-17) are as self-explanatory here as anywhere else.

It is `FAIL`, not `CONCERNS`, because the thing that must be trustworthy — "did this run pass?" — cannot be trusted as specified:

- **The gate command does not run.** `scripts.test` and the capstone both specify `node --test example`. On current Node (v24.16.0, verified in this worktree) a bare directory positional is **not** a valid test argument: Node tries to load it as a module and exits 1 (`MODULE_NOT_FOUND`). Node's CLI accepts **glob patterns** (docs: "one or more glob patterns … as the final argument(s)"), e.g. `node --test "example/**/*.test.js"`, or a bare `node --test` run from inside `example/`. The design's stated rationale for scoping it is also inverted: the default discovery patterns are recursive (`**/*.test.js` …), so bare `node --test` at the root **does** find `example/*.test.js` — it does not "discover zero tests".
- **Even when corrected, the check can be vacuously green.** `node --test` exits **0 over zero discovered tests** (verified: empty scope → `tests 0 … pass 0`, exit 0). The design deliberately removes the executed-count wire (§ Decisions: "One job removes the executed-test-count wire, a silent breakage point"), so a run whose build wrote the page but no test file passes `node --test` green + sentinel gone + PR merged. That is not merely a gap: it is a false "success" entering the benchmark, and it inverts the demo (the reviewer catching a trap is the moment the demo exists to show).
- **The privacy guarantee is not the one stated.** The design says the runner scans the run diff pre-push because "a post-push scan is too late". But the runner runs at **run start**; the commits that carry the leak-prone artefacts (`docs/` logs, `status.jsonl`, screenshots) are produced and pushed by the **workflows**, not the runner. The PR-only step fires after those commits are already public. So the irreversible branch has late-only detection — on a public repo.

Two further points: the off-disk blank-page failure (mode 13) still has no signal beyond prose, and `main` mirror drift (mode 2) is invisible at run time. Neither alone would sink the design; together with the two above, they leave the operational floor below what "the only thing that fails a run" should sit on. All four are bounded fixes — none requires new infrastructure — which is why they are `CRITICAL`, not an argument to abandon the design.

**`Risks & Open Questions` cross-check.** Covered: reset scope, always-latest breaking release, public privacy, double-click contract, root-harness drift, sentinel rot, ledger growth, human hard stops, AI non-determinism, failed-run clutter, Node version, `main` mirror drift, skeleton stability. Missing from Risks (each is also a finding): the vacuous zero-test green (CRITICAL 2), the invalid pass/fail command form (CRITICAL 1), the privacy pre-push window (CRITICAL 3), and bootstrap partial-failure recovery (OPTIONAL). No open question lacks an option / `Recommended` / `Default if unanswered`.

## CRITICAL

1. **The pass/fail command is invalid as specified (mode 8).** `scripts.test` and the capstone both use `node --test example`; on current Node a directory positional throws `MODULE_NOT_FOUND` and exits 1 (verified on v24.16.0). Resolution: use a glob (`node --test "example/**/*.test.js"`) or run `node --test` from inside `example/`, and record the exact form in the fixture and capstone. Correct the design's premise too — bare root `node --test` is recursive and **does** discover subfolder tests.
2. **The gate can be vacuously green (mode 9).** `node --test` exits 0 over zero discovered tests (verified), and the design removes the executed-count wire. A run can merge green with the logic untested. Resolution: assert an executed-test count ≥ 1 in the capstone (or assert the fixed test filename exists) so `green == validated`; keep trap-catching itself measured, never gated.
3. **The privacy guarantee does not cover pipeline pushes (mode 15).** The runner scans only the reset diff pre-push, but the leak-prone artefacts are committed and pushed by the workflows and become public before the PR-only scan. Resolution: either move the privacy assertion into a step that runs on **every** push (accepting that it must not depend on the built page, so the reset push stays green), or have the runner own the run's pushes; state the guarantee honestly either way. This is the only irreversible path on the design.
4. **The off-disk blank-page failure still has no signal (mode 13).** `node --test` guards the logic file's dual-load, not the HTML script tag; adding `type="module"` blanks the page while CI stays green. Resolution: fold a deterministic classic-script assertion into the PR-only step that already reads the built `index.html` — same step, no new machinery.

## OPTIONAL

- **Runner transition lines (mode 1).** Emit one `[bkit-example]` line per transition (repo-created, fixture-copied, install-done, start-command-printed) so a mid-sequence stall is attributable to a step; name the half-seeded repo path in the failure output.
- **Bootstrap partial-failure repair (mode 1).** State the repair path when `gh repo create` succeeded but seeding failed; verify-mode covers re-runs in principle but the design does not say the half-seeded state is repaired.
- **Post-delete verification for the one destructive op (mode 4).** After the scoped delete, assert (and log) that every removed path resolved under `example/`; the pre-delete assertion guards intent, this guards reality.
- **`main`-drift check at run preflight (mode 2).** Have the runner assert `main` still holds the fixture sentinel at run start, not only during bootstrap — cheap, and it removes the silent stale-start-state class.
- **`[skip ci]` recovery line (mode 11).** Add the recovery (remove the inherited suppression token, re-push) to the `examples/README.md` contract table beside the KN-11 reference.
- **Breaking-release unblock runbook (mode 5).** "Always-latest" is binding, so document what an operator should do when a release blocks the sweep (and that there may be nothing to do but wait) rather than leaving a documented dead-end.
- **Overlapping-run guard (mode 18).** The design already names a lock as the mechanical upgrade; a cheap git-ref/lock check would turn the serial invariant from a convention into a boundary.
- **Sentinel single source (mode 16).** Define the sentinel string once so an edit to the placeholder copy cannot drift the fixture from the check.
- **`data.js` owner-check (mode 17).** Adopt the draft's recommended option — the per-release canary owner checks the phase list, loop caps and hard-stop placement.
- **Screenshot-failure loudness (mode 22).** Log a failed capture loudly (still non-gating) so a missing artefact is visible rather than silently absent.

## OUT OF SCOPE

- **Cost/token observability.** No source exists (`.bkit/stats.jsonl` carries no usage rows); deferring to #526 is correct — measuring-only, never gating.
- **Metrics / traces / dashboards / alerts.** The project operates with no telemetry pipeline (`docs/observability.md` § Scope); service-grade expectations would be out-of-stack.
- **AI non-determinism of trap-catching.** Measured, never gated (#232); not an alert, and the demo must not promise a catch — correctly designed.
- **Human hard stops.** Inherent to the pipeline; they bound automation but are not an operability defect.
- **`bkit install`/`doctor` tracker-`none` advisory.** A bkit-side behaviour change, deferred; not part of this example.
- **The nine later ideas from #504.** Deferred by the design; out of this cycle.
