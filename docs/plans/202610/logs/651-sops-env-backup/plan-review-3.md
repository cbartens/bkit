## OPTIONAL

- **Stale-backup-while-green (knowledge `kn-lint-prose-gitignored-styles-silently-disable-gate-in-worktrees`, ACTIVE).** If `sops` is absent or below `MIN_SOPS` on a machine that holds the key, the hook warns, exits 0, and the backup silently ages. Most bkit commits are agent-made, and agents may not act on hook stderr. The plan's own Q4 rationale ("a silent skip leaves a stale backup that looks current") applies here. Consider: when a SOPS key file is present but `sops` is unusable, stop the commit, or print the warning on every commit, plus a row.
- **Hook dispatch fidelity (rows 21-22).** The tests wire templates through `core.hooksPath <tmp>/.husky`, so git runs each hook directly. Production runs through `.husky/_/h`, which uses `sh -e "$s"`, prepends `node_modules/.bin`, and honours `HUSKY=0`. The post-commit template is written "no `set -e`" but runs under `-e` in production. Add one row that dispatches through a husky-style wrapper, or state why the two paths are equivalent. Test copies need the exec bit.
- **SOPS env hermeticity in EB.** `vitest.setup.ts` scrubs `GIT_*` only. Build the EB child env with `SOPS_AGE_KEY`, `SOPS_AGE_KEY_CMD`, `SOPS_AGE_SSH_PRIVATE_KEY_FILE` and `SOPS_AGE_RECIPIENTS` removed, so a developer's real key settings never reach a test.

It is gitignored by `.env.*`, so the next run treats it as a plain env file. Its copy `….tmp-PID.enc` matches `!.env.*.enc` and gets committed.
