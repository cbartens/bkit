## Context & Goals

bkit subagent and `bkit-ship` rebase friction observed 2026-05-06 → 2026-05-08 keeps recurring at higher load points after the BAR-137 stub-first fix shipped. Remaining shapes:

1. Freeform review/audit agents (no `echo >>` log) still budget-exhaust → silent `Verdict: PENDING` (BAR-93 challenge re-run, BAR-141 plan-execute on bkit, BAR-132 sub-plan-1 on visitfrasercoast-com).
2. `bkit-plan-generate` stream-times-out on 32 KB multi-issue input (BAR-131/139/142 combined) — no output.
3. Single-reviewer `bkit-build-challenge` has same-model blind spots — pattern inconsistent with `bkit-design-review-1/-2`, `bkit-plan-review-1/-2` parallel pairs.
4. `bkit-ship` Step 2 `git rebase origin/dev` exits via bare `exit 1` on conflict, bypasses Failure Path → `bkit-debug-abort-handover` never fires for rebase aborts. Drift accumulates because builds emit no signal that the branch is behind `dev`.

This plan implements six fixes (1b, 2, 3, 4a–d, 5, 6) prescribed in the Linear issue. **No new design work.** All changes are in `.agents/*` (canonical sources only); `.claude/`, `.cursor/` mirrors are regenerated by `bkit install` at end-of-session.

**Path note for execution:** Linear issue references `.agents/agents/*.md` for Claude subagents. Actual canonical location in this repo is `.agents/prompts/*.md` (verified via `Glob`). All references below use the actual path; functional intent is unchanged.

**Success Criteria:**

- All Fix-1b target prompts (`bkit-build-challenge-1`, `bkit-build-challenge-2`, `bkit-build-plan-verify`, `bkit-build-challenge-tests`) emit incremental `echo >>` finding entries and eager `Verdict:` flip-on-BLOCK; audit pass over `bkit-utility-audit-*` confirms no remaining gaps.
- `/bkit-plan` deterministically routes >15-task plans and multi-issue (`BAR-N` count > 1) plan-inputs to Failure Path; existing 100K-token gate retained.
- `/bkit-build` Step 9 launches `bkit-build-challenge-1` and `-2` in parallel; `bkit-build-challenge-reconcile` produces drop-in `build-challenge.md` consumed unchanged by Step 10 remediate.
- `/bkit-ship` Step 2 rebase failure routes through Failure Path; `ship-handover.md` produced automatically by existing `bkit-debug-abort-handover` agent.
- `/bkit-build` Step 1 always emits `[bkit-build] feature branch is N commits behind dev / M ago since divergence`.
- Index docs (`.agents/workflows.md`, `.agents/prompts.md`) reflect every prompt/workflow change. Template sync verified for any `bkit:start/end` block edit. `bkit install` runs ONCE at end-of-session.

### Spec — what good looks like

- **Narrative:** A bkit user invoking `/bkit-plan`, `/bkit-build`, or `/bkit-ship` either gets a clean run, OR a deterministic Failure-Path artifact (handover doc, split-required notice, multi-issue refusal) — never a silent `Verdict: PENDING` log file or a bare `exit 1` rebase abort.

- **Key Edge Cases:** Concurrent edits to mirror block; partial completions across `.agents/prompts/`, `.agents/workflows/`, index files; template-sync drift; `bkit install` failures mid-session.

  - **Setup:** Developer invokes `/bkit-plan BAR-131 BAR-139 BAR-142` against existing `plan-input.md` containing all three issues (>2 `BAR-N` tokens, ~32 KB).

## Alternative Approaches & Recommendations

Considered and rejected (per Linear issue Out of Scope):

- **Diff-size or sensitivity gating** for parallel challenge — explicitly always-on; cheaper than threshold-based logic that gets ignored when it doesn't trigger.
- **`task-range` parameter for `bkit-build-plan-execute`** — deferred fallback; revisit only if Fix 2 (>15 task gate) proves insufficient.
- **Focused-brief mode for `bkit-build-challenge`** — explicitly dropped. Diversity (Fix 4) over narrowing.
- **Retrofit of `bkit-design-review-*` and `bkit-plan-review-*`** with explicit model/thinking diversity — already verified Opus/high vs Sonnet/medium.
- **Subagent retry/backoff harness redesign** — out of scope; prompt/structure changes only.
- **KN/DE auto-renumber on rebase conflicts** — explicitly dropped; sed regex / cross-platform fragility.
- **Template-vs-canonical preference rule on rebase conflicts** — explicitly dropped; manual resolution acceptable for this frequency.
- **Custom `ship-rebase-conflict-{N}.md` artifact** — superseded by Fix 5 (existing handover format suffices).
- **Opt-in mechanism for multi-issue plan-input** — explicitly refused via Failure Path; no flag, no marker.

Future-phase recommendations (DO NOT include in this PR):

- After 2 weeks of production use, re-evaluate if 15-task cap is right boundary. Linear issue notes 18 = highest clean, 20 = lowest dirty; 15 chosen as safety margin.
- If reconciler downgrade-with-justification path gets used, examine which finding shapes most often justify downgrade — may inform a structured `severity-rationale` field.
