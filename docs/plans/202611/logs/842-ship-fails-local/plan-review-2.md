## CRITICAL

1. **R1 — Make cleanup conditional on the exact refs it proved safe (plan edit).** Task 4 fetches and inspects local and remote tips, but its required test only advances the remote before that inspection. Current `deleteBranch` runs an unconditional `git branch -D` and `git push origin --delete` (`.bkit/core/engine/commands/workflow/worktrees.ts:671` and `:674`). A second session can push a fix after the final safety read and before deletion; the proposed read-then-delete sequence still deletes that fix. Bind deletion to the exact inspected local and remote commit identifiers, preserve/report either ref when it moved, and handle a remote disappearance without deleting a recreated branch. Add a real bare-origin regression that advances the remote between the safety proof and the delete attempt and asserts the newer ref and its content survive. Use a compare-and-delete operation or retain the ref when that guarantee is unavailable; another final read alone does not close this race. This is distinct from the acknowledged non-atomic `dev` merge window: the destructive branch mutation itself must reject a changed expected value.

2. **R2 — Recheck inherited dev work on the reconciled tip before publication (plan edit).** Task 2 extends the setup-time refusal, while Task 1 later imports remote feature commits. The reused `inheritedDevCommits` examines only the named local branch (`.bkit/core/engine/commands/workflow/worktrees.ts:230-238`), and its existing setup call passes `target` (`:989`). A local feature tip can be clean while `origin/feature` contains a commit also present on unpublished local `dev`; setup accepts the old local tip, then reconciliation imports the forbidden commit. Require the early check to inspect the freshly fetched remote tip as well, and/or check the resulting reconciliation head before the first push or PR creation. Add a scenario with a clean local feature, an ahead/diverged remote feature containing unpublished local-dev ancestry, and assert refusal with commit identifiers and no publication. Include a remote advance discovered on a retry, so the initial setup proof is not reused after the candidate head changes.

3. **R3 — Carry the new safety decisions through the MCP transport path (plan edit).** Tasks 3, 5 and 6 add behavior inside gh-backed engine calls, but Task 7 and its tests only name the normal engine outcomes. The current fallback maps probe to `list_pull_requests` and gate to `actions_list` (`.bkit/core/workflows/bkit-ship.md:39`); the merge fallback reduces the reread to MERGED versus FAIL (`:624`), which feeds the existing CI-diagnosis route. `runGate` returns 80 before ancestry checks when the PR probe is unavailable (`.bkit/core/engine/commands/workflow/runs.ts:1998-2000`), and `mergePr` likewise returns 80 before its post-attempt classification (`prs.ts:493-497`). Rendering the same prose for five hosts does not exercise this transport. Specify how MCP-returned PR/base evidence reaches the same deterministic eligibility, stale-base and merge-refusal decisions; fail closed when the evidence cannot be supplied. Add matrix rows and task-owned tests for gh unavailable with an old merged PR plus newer work, stale dev with green CI, and a moved-head/conflicting merge refusal. Assert the new-PR, integration or validation route and that none bypasses the gate or enters CI code remediation.

4. **R4 — Compare Git tree-entry metadata when deciding work is landed (plan edit).** Task 4 adds deleted-file handling to the shared comparison but retains content-equivalence wording and tests only additions, edits, deletions and ledger rows. Current `notOnDev` compares `rev-parse ref:path`, which returns the object identifier, not the entry mode (`.bkit/core/engine/commands/workflow/branches.ts:2868-2873`). An executable-bit-only change has the same blob on both branches and is therefore judged landed even when `dev` lacks it; the same issue applies to a regular-file/symlink change with identical blob bytes. Specify comparison of entry mode/type as well as object content, retaining the deliberate ledger semantics. Add real-Git tests for an unlanded executable-bit change and a type change, with a positive squash-equivalent case. Include the existing design/plan land caller in regression coverage because it adopts the same changed helper.
