## CRITICAL

1. **(plan edit) Group 1's engine commits need a rebuilt `dist/`, but only Task 6 in Group 2 builds it.** Tasks 1, 2 and 3 edit `.bkit/core/engine/commands/workflow/tests.ts` and `steps.ts`. Each code step's `steps finish` commit runs `.husky/pre-commit:18-22`, and this worktree has `.husky/_` installed, so the hook runs. The hook runs `pnpm bkit:check:dist` (`package.json:88`: `rm -rf dist && tsc && … git diff --exit-code dist/`) whenever a non-test `.bkit/core/engine/**/*.ts` file is staged. A Group 1 commit without a matching staged `dist/` is refused, and `.agents/rules.md` § Engine builds and `docs/knowledge.jsonl` key `kn-7-dist-staleness-pnpm-build-must-run-before-push-for-bk` require `pnpm build && git add dist/` in the same commit. The plan has `[MODIFY] dist/` rebuilt "after the engine edits" and puts `pnpm build` only in Task 6's `DONE WHEN`. So the artefact that Group 1's commits consume is produced only by a later group. Fix: add `- **UPDATE:** \`dist/\`: \`pnpm build\`, staged with the engine edit` to Tasks 1, 2 and 3, add "`pnpm build` exits 0 and `dist/` is staged" to each one's `DONE WHEN`, and keep Task 6's build only as the final re-check.

2. **(plan edit) Task 4 breaks the `bkit-build` render baseline, and no task updates it.** `.bkit/core/engine/render/trackers.test.ts:399-403` (`bkit-build: the none render matches its baseline byte for byte`) compares the none render of `.bkit/core/workflows/bkit-build.md` with `.bkit/core/engine/render/__snapshots__/bkit-build.none.txt`. Task 4 edits that workflow in Step 7, Step 9, Step 10, Step 15, § Decision Pause and Gate 15, so the unit-tier test goes red. Neither Task 4 nor Task 6 names the snapshot. Task 6's `DONE WHEN` runs `pnpm bkit:gate:static` only, which runs no unit test, so the plan never says what turns it green. Fix: add `- **UPDATE:** \`.bkit/core/engine/render/__snapshots__/bkit-build.none.txt\`: regenerated (\`vitest -u\` on \`trackers.test.ts\`) after the workflow edit, reviewed` to Task 4, and add "`trackers.test.ts` passes" to its `DONE WHEN`.

3. **(plan edit) Task 2 changes the shape of the exit 11 `tests` output but does not name the existing tests it breaks.** Task 2 makes `touchedTests` return `{task, test, name, block}`, and `finish` emits that list as `tests` (`steps.ts:1269-1275`). The existing suite asserts `expect(r.json.tests).toEqual([{ test: TEST.file, name: TEST.name }])` at `.bkit/core/engine/commands/workflow/steps.test.ts:1877` and `:1894`, and `toEqual` fails on the extra keys. Fix, either way: (a) add `- **UPDATE:** \`.bkit/core/engine/commands/workflow/steps.test.ts\`: the two existing \`r.json.tests\` assertions take the new \`task\` and \`block\` keys`, plus "the rest of the suite still passes", to Task 2; or (b) keep the emitted `tests` as `{test, name}` and use `task` and `block` only inside `finish`. Under (a), also add the `tests` shape change to `Breaking Changes` (the exit-code help at `steps.ts:1809` documents `tests: [{test, name}]`).
