No `Reuse Inventory` row names it, so the plan builds a second reader. Split out a `reportFailures(dir): JunitCase[] | null` that `countReportFailures` and `tests base` both use. Add the change to Task 1 or Task 5.

2. **(plan edit) A red gate with zero failing JUnit cases has no defined result, and it can break SC3.** The gate can exit 1 with reports present and `failures` = 0. Two ways this happens: a static check fails after the unit run, or the runner fails without a failing case (a coverage threshold or an unhandled error). Task 3 then adds 0 to each round, so the pause shows "0 → 0". SC3 says "a red gate never shows as '0 → 0'". `baseVerdict(cases)` (Task 4) receives an empty failing set. The Architecture's `unknown` reasons do not cover that set, so an "every case is base-red" check passes when there are no cases, giving `all`. The pause would then recommend `Stop` with "these 0 tests fail on `dev` too". No `Edge Cases` row, `Derived Test Matrix` row or `TEST FIRST` test covers this. Fix: add an Edge Cases row ("gate red, 0 failing cases"). Define the round count (`?` / trend `stuck`, as for a null count) and the verdict (`unknown`, reason such as `gate red with no failing test case`). Add matrix rows and `TEST FIRST` tests in Task 3 (`counters.test.ts`) and Task 4 (`tests-base.test.ts`). Both tasks are under the 10-test cap.

3. **(plan edit) The tracked-file guard that `Security & Privacy` claims is neither built nor verified.** `Security & Privacy` › **User Input** says: "Test file paths come from JUnit reports and are used only when they are tracked files (`git ls-files`), so a report cannot point the runner outside the repo." Task 4's `caseFile` takes "file attribute, then a tracked `classname` path, then exactly one matching tracked basename". The `file` attribute is accepted first, with no tracked check. Architecture `tests-base.ts` step 1 says the same. No matrix row or `TEST FIRST` test checks that an untracked or outside-repo `file` value (`../x.test.ts`, an absolute path) is rejected. Fix: make `caseFile` require every candidate, `file` included, to be a tracked repo-relative path. Add a matrix row and a Task 4 `TEST FIRST` test such as `caseFile > an untracked or outside-repo file attribute leaves the case undetermined`.

4. **(plan edit) The headline output of SC1 has no test.** SC1: "the pause says how many failing tests also fail on the base commit: all, some, none, or 'can't tell' with the reason". That count is the progress line `Also red on base {base}: {baseRed} of {failing} ({source} run)` (Architecture `decisions.ts`; Concrete Example step 3: `Also red on base {sha}: 3 of 3 (local run)`). None of Task 6's 8 `TEST FIRST` tests asserts the line; they assert only the recommendation and the reason. The line is also undefined for verdict `unknown`, where `base` and `source` can be null (`no base commit`, `no JUnit report`). Fix: define the `unknown` form of the line. Add a matrix row and a Task 6 `TEST FIRST` test, e.g. `bkit decisions compose > base check prints how many failing tests are also red on base` failing on the file lacking "Also red on base". Task 6 then has 9 tests, under the cap of 10, and group 2 has 24 of 25.
