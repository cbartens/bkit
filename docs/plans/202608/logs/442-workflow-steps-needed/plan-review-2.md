So the moment Task 13 makes `plan-review-2` / `-3` conditional, the very run the Concrete Example describes (step 3, two lenses skipped) hits `:498` and fails. Missing prerequisite for Tasks 12 and 13: a wave-2 task that makes each fan-out step assert only the artifacts whose lens ran, sum over present reviews, and emit a variable-length `artifacts` array + skip-aware gate items.

2. **`path-override` is a dead `decidedBy` arm, and the test that forbids dead arms is scheduled before the wave that would populate it.** The enum member is defined for "a lens forced **on** by `bkit.sensitivePaths` that its own predicate would have skipped" (Architecture § wave 1 bullet 4; Task 13). So no `route_append_step_skipped` call site can legitimately carry `path-override`, yet the Derived Test Matrix row "every enum member has at least one call site (no dead enum arm)" and Task 5's `Done when` both require one. Independently of that, Task 5 lands in wave 1 while `sensitivePaths` lands in wave 3 (Task 13), so even under a workable definition the audit is red from Task 5 until Task 13 — a backwards dependency across three waves. Either give `path-override` a real skip-emitting meaning (e.g. a _complementary_ row type / a `decidedBy` recorded on the forced-on `step-done`), or drop the arm and the matrix row with it.

3. **Task 9 hard-sets two variables on skip arms that do not exist — one not yet, one not ever.** Verified against the tree: the 28 conditional steps are `bkit-design.md:501/714/838` and `bkit-plan.md:743/858`.
