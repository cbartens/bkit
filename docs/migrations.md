# Migrations

> [!CAUTION]
> **Purpose:** The register of every upgrade migration in the engine. A migration is code that rewrites a consumer file left by an older bkit release, so that `bkit upgrade` alone brings the file up to date.
>
> **Rules:**
>
> - Follow `.bkit/authoring.md` § All Agent-Read Files and § Docs when you edit this file.
> - Give each migration one row.
> - Add the row in the same change that adds the code.
> - Delete the row in the same change that deletes the code.
> - A migration is idempotent, runs inside the normal install / upgrade write path, and has a test that seeds the old shape. In that path, a dry run must compute the same writeset.
> - Name the release range each migration covers, so that a later sweep can retire it once no supported install predates it.
> - Detect-only checks, which tell the human to fix something by hand, are not migrations. They live under § Detect-only guards.
